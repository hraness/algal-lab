# SNI size32 executor protocol v1 (2026-10-13)

**Agent-decided, owner may revisit. Offline specification only; no blob fetch is authorized by this file.** The decision, split, source revision, 32 exact rows, bytewise selection rule, prior 64 consumed attempts and $0 model allowance remain fixed by [the pre-access freeze](sni-size32-freeze.md). The [independent selection review](sni-size32-independent-review.md) checked the arithmetic, not this executor. This protocol freezes behavior and fault tests **before** implementing or using a fetcher. A successful fetch yields metadata for review, never rights or family admission.

## Inputs and output boundary

Only the existing private `runs/sni-size32-20261013-01/` may be used for live execution; no replacement directory resets the 32-attempt allowance. Re-read `plan.json` and `selection.tsv` before the first request: require the exact pinned commit/tree/index/previous-selection/test-name/size-manifest/selection identities, zero initial counters and charges, the numeric limits below, SHA-256 of the selection bytes `6ea37fc2bff821ed5cbd5f10352c98b451442f29ee5dbf6bc2029c340c069388`, 32 distinct train rows with valid task IDs/OIDs and declared nonnegative sizes <=1,000,000 in bytewise task order. Require only the three expected preflight files and no attempt/result/report files before starting. Any existing attempt record, terminal file, unexpected file or uncertain directory state is a **stop**, not a resume invitation. A separate immutable private selection and previous-attempt review already exist; the executor does not reconstruct the sample from task bodies. Production entry must not expose a command-line option for changing the source, row set, byte limits or live output directory.

Attempt `NN` (01–32) strictly in TSV order, maximum one HTTP request per row; no retry, replacement, automatic redirect, request for test/excluded tasks, or model call. First write `NN.attempt.json` *exclusively*, awaited, mode 0600, with exactly `task`, `blobOid`, `status: "started"`. If it throws, **do not request** and stop; a partial file is unresolved. Only then request `https://raw.githubusercontent.com/allenai/natural-instructions/<pinned-commit>/tasks/<selected-task>.json` with `redirect: "error"` and a per-request 30,000 ms deadline covering the body, not just response headers. Reject non-200 statuses and absent bodies without reading error bodies. Ignore content-length as an authority to parse, but reject a finite header above the remaining body/aggregate budget before reading. Cancel/release the body on all exits; cancellation failure is a safe terminal failure if an otherwise complete response cannot be closed, and an uncertain terminal write is still a stop.

Count **actual response-body bytes emitted to the application by stream reads**, including the entire first chunk crossing a cap; do not count headers, JSON characters, claimed content-length or unused selection metadata. Record `observedBytes` for each attempt, zero if no chunk was yielded. Accepted chunks are stored in bounded process memory only. At most 1,000,000 body bytes may be accepted per request and at most 32,000,000 in aggregate; if a chunk would cross either cap, count its full observed length, discard it without copying/decoding, cancel, and emit `blob-too-large` or `aggregate-limit`. Such a terminal failure can report observed bytes above the cap by up to the transport's indivisible chunk; **never hide those bytes or make another request once the aggregate cap is reached or crossed**. Before a request with no remaining aggregate budget, stop with no attempt file or request. Track actual observed bytes through failures, timeouts and transport errors; the report sums them, not the selected Git tree sizes. A timeout uses the same safe record with its observed byte count. Bounds are best effort over bytes emitted by the stream, not a claim about remote or OS-buffered bytes.

Check complete response size against selected tree metadata size, then Git SHA-1 of `blob <byte-length>\0<bytes>` against its exact selected OID, **before** UTF-8 decoding and JSON parsing. Header length alone proves neither. Decode UTF-8 fatally, parse JSON from unknown, require an object, and project only `task`, `Source`, `Categories`, `Instance License` using the existing closed metadata parser. No raw JSON, `Instances`, labels, examples, URLs, response error text or arbitrary thrown messages may enter files or logs. Exactly one exclusive terminal `NN.sidecar.json` (only OID plus four metadata fields and `observedBytes`) **or** `NN.failure.json` (only `task`, `blobOid`, enumerated safe `code`, `observedBytes`, fixed disposition) follows an attempt. OID mismatch, size mismatch, invalid UTF-8/JSON/metadata, body/aggregate limit, HTTP/redirect, timeout and generic transport failure are safe terminal failures. A terminal file write error is **not** a recoverable extraction error: do not write the opposite outcome, retry, summarize as success or start the next attempt. Stop with the started slot unresolved. The same applies to cleanup uncertainty or loss of exclusive output custody. No report is emitted until all 32 slots have exactly one terminal outcome; an exclusive report write failure remains unresolved. An exclusive report contains counts and the sum of per-attempt observed bytes, no body or claim of group eligibility; files, not mutable counters, are authoritative.

## Synthetic acceptance tests, before live access

Use an isolated new temporary directory with copies of the exact preflight plan and selection, an injected fake fetch and exclusive write function; no real network. Assert exact URL/order and immutable selection rejection. Prove no request when a preflight/attempt write fails; no second request after a terminal write failure (including a write that creates a file then throws), and no fallback failure next to an uncertain sidecar. Test a complete valid synthetic Git blob separately from the live selection, OID mismatch before parse (malformed JSON with wrong OID), size mismatch, fatal UTF-8, invalid JSON/metadata and exact closed sidecar. Test 200/no body, non-200 (body not read), redirect rejection, thrown fetch, timeout after a partial chunk, misleading content-length, exactly-at-limit and over-limit chunks, aggregate crossing, and no further request after exhaustion; assert observed-byte totals even on failures. Run focused size32/intake/train64 tests, typecheck, `git diff --check`, then request independent exact-byte review of protocol, source, tests, and private-ledger shape. Do not fetch any selected blob until those gates pass. Later delivery needs `bun run check` on the exact isolated tree and PR-head `Required`; the prior aggregate timeout is not a pass. Rights/aliases, untouched holdout, numerical comparison and paid model allowance remain separate gates.
