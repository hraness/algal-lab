# Failure-aware execution: prospective provenance gate v2

**Frozen test-only decision, 2026-10-09.** Can a future *local fixture* attempt durably reserve its whole allowance before executing, and retain replayable raw single-host-PID RSS readings? This is a new protocol for instrumentation qualification, not an amendment to, repeat of, or refund for `host-comparison-2026-10-08-v1`. The v1 source identities, two charged attempts (first `/bin/ps` `EPERM` before timing; second six passing correctness groups and three repetitions per host), and independent provenance/RSS qualifications remain historical. No full comparison attempt is authorized here; paid allowance and calls: **$0 and zero**. No provider, holdout, production, runtime-ranking, or novelty claim follows.

The intended consumer is an independent reviewer deciding whether a **later, separately allowed** comparison has trustworthy timing and host-only memory provenance. Baselines remain Bun, OTP, synced intent without automatic retry, and provider idempotency only under a guaranteed external contract. The existing local effect-log oracle and canonical receipt checks remain mandatory; a logged local effect does not prove an external effect. There is no new workload, selection, hypothesis test, or final holdout in this gate. The independent unit of a later comparison would still be a complete host/scenario repetition; the six-group correctness, zero duplicate fixture effects, matching receipts, and three alternating repetitions per host are necessary but not sufficient.

## Test-only procedure (frozen before implementation)

1. Create a **new empty, private directory** with an exclusive create. Write a strictly parsed, bounded reservation containing a unique attempt ID, source identity, full whole-attempt allowance, and previous charged count. Sync the reservation file and directory **before** invoking any supplied execution callback. Never reuse a directory or refund a failed/uncertain attempt. This test probe does not authorize a new attempt; a real attempt needs a new external allowance decision before this step.
2. An independently retained *pre-execution* witness of the exact reservation SHA-256 is required for any later historical claim about reservation chronology. A timestamp or hash stored only by the writer after the fact is not an independent witness. The test probe takes a witnessed digest as input and refuses a missing/mismatched witness, a corrupted reservation, or an existing start marker; sync a marker referencing the reservation before calling the bounded callback. Probe tests read back the reservation and marker **inside** that callback. A later reviewer must retain the witness outside the run writer's control and inspect the admitted source and filesystem sequence; do not infer the real v1 attempt's timing from this new code.
3. On Darwin only, take exactly ordered `proc_pidinfo`, `proc_pid_rusage`, `proc_pidinfo` readings from a declared live child host PID, retaining PID, source, monotonic nanosecond timestamp, and raw resident bytes at every read. The reported byte count is the final `proc_pidinfo` reading. Both OS APIs share kernel accounting; this is host-only RSS, not independent physical memory or the worker/process tree. The independent reviewer replays strict newline-terminated JSONL against the **separately declared** spawned host PID, the three source labels/order, strictly increasing timestamps, at most 500 ms from first to last read, positive safe-byte integers, and reference inside the bracketing range plus 65,536 bytes. Each sample has a consecutive index; audit requires the declared count, baseline, and peak to agree. No off-Darwin fallback, substitute zero, missing sample, or silently repaired line is accepted for this gate.
4. A truncated, malformed, duplicate, extra-field, inconsistent, or foreign-PID sample fails closed; missing/corrupted reservation, marker, witness, and sequence fail closed before execution. An interruption during or after an effect remains **uncertain**; no test may infer success from the RSS trace, regenerate a missing effect row, or automatically retry. Retain the original effect log and the v1 independent oracle rather than using RSS as an effect oracle.

Acceptance requires an independent reviewer to read the frozen protocol and source, reproduce the test-only chronology and raw-sample replay (including corruption/uncertain-effect adversarial controls), and explicitly distinguish a test of the path from historical proof of a **future** real run. The future comparison harness must be wired to the reservation gate, independently witnessed *before spawn*, retain its actual host spawn PIDs and synced raw traces including failures, and pass separate permission, freeze, allowance, and review before any benchmark. Until then **no v2 comparison or performance claim is admitted**. Test-only mutations use temporary owned directories, no model calls, and no effectful provider actions.
